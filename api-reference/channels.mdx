title: Canais

Um canal representa um número WhatsApp conectado ao Coexy. Após criar um canal, compartilhe o `connect_url` para que o responsável pelo número faça a conexão via WhatsApp Embedded Signup.

## Tipo Channel

```typescript
type Channel = {
  id:                   string        // UUID
  name:                 string
  status:               'pending' | 'active' | 'disconnected' | 'suspended'
  display_phone_number: string | null // ex: "+55 11 99999-9999"
  phone_number_id:      string | null // ID do número na Meta — usar como {entity_id} no meta-proxy para enviar mensagens
  waba_id:              string | null // ID da conta WhatsApp Business — usar como {entity_id} no meta-proxy para templates
  channel_token:        string        // Bearer token do meta-proxy (Authorization: Bearer)
  connect_url:          string        // https://coexy.com.br/connect/<token>
  connected_at:         string | null // ISO 8601
  token_expires_at:     string | null // ISO 8601
  created_at:           string        // ISO 8601
}
```

## Status do canal

| Status | Significado |
|--------|------------|
| `pending` | Canal criado, aguardando conexão do número WhatsApp via `connect_url` |
| `active` | Conectado e funcionando — tokens são renovados automaticamente pelo Coexy |
| `disconnected` | Token revogado pela Meta (ex: mudança de senha, remoção de permissão) — requer reconexão via `connect_url` |
| `suspended` | Suspenso administrativamente |

<Info>
**Tokens são gerenciados automaticamente pelo Coexy.** Após conectar o WhatsApp, você não precisa se preocupar com renovação de tokens — o Coexy cuida disso. Em casos raros (ex: revogação de permissão na Meta), o canal muda para `disconnected` e você deve reconectar pelo `connect_url`.
</Info>

## Fluxo de conexão

1. Crie o canal via `POST /channels` — ele nasce com status `pending`
2. Compartilhe o `connect_url` com o dono do número WhatsApp
3. O dono acessa o link e autoriza via WhatsApp Embedded Signup
4. O canal muda para `active` e os campos `phone_number_id`, `waba_id` e `display_phone_number` são preenchidos

<Warning>
`phone_number_id` e `waba_id` só ficam disponíveis **após a conexão**. Antes disso, são `null`.
</Warning>

## Endpoints

### Listar canais

<ParamField header="x-api-key" type="string" required>
  Sua API Key
</ParamField>

```bash
GET /channels
```

```bash
curl https://api.coexy.com.br/functions/v1/api/channels \
  -H "x-api-key: crt_pk_sua-chave"
```

**Resposta:** `Channel[]`

---

### Criar canal

```bash
POST /channels
```

<ParamField body="name" type="string" required>
  Nome identificador do canal
</ParamField>

```bash
curl -X POST https://api.coexy.com.br/functions/v1/api/channels \
  -H "x-api-key: crt_pk_sua-chave" \
  -H "Content-Type: application/json" \
  -d '{ "name": "Suporte Principal" }'
```

**Resposta:** `Channel` — status `201 Created`

Após criar, compartilhe o `connect_url` retornado para que o número seja conectado.

---

### Buscar canal

```bash
GET /channels/:id
```

```bash
curl https://api.coexy.com.br/functions/v1/api/channels/uuid-do-canal \
  -H "x-api-key: crt_pk_sua-chave"
```

**Resposta:** `Channel`

---

### Deletar canal

```bash
DELETE /channels/:id
```

<ParamField query="force" type="boolean">
  Obrigatório se o canal está com `status: active`. Use `?force=true` para confirmar.
</ParamField>

```bash
curl -X DELETE "https://api.coexy.com.br/functions/v1/api/channels/uuid-do-canal?force=true" \
  -H "x-api-key: crt_pk_sua-chave"
```

**Resposta:** `204 No Content`

## Erros

| Status | Mensagem | Causa |
|--------|----------|-------|
| `404` | `Channel not found` | ID não existe ou não pertence à sua org |
| `409` | `Channel is active. Use ?force=true...` | Tentou deletar canal ativo sem `?force=true` |
| `422` | `"name" is required` | Body sem o campo `name` |
