<Warning>
**O que NÃO fazer:**
- Não invente endpoints de envio — use a mesma estrutura da [documentação da Meta](https://developers.facebook.com/docs/whatsapp/cloud-api/reference), trocando apenas a base URL e o token
- Não chame `/meta-proxy` ou `/api` direto do frontend (React, Lovable, Bolt) — credenciais ficam expostas
- Não confunda `COEXY_API_KEY` (Management API) com `channel_token` (Meta Proxy) — são credenciais diferentes
- Não recrie o canal ao receber erro 503 — basta reconectar via `connect_url`
</Warning>

## Como funciona

```
Usuário WhatsApp → Meta → Coexy → Webhook → Seu servidor
                                ↑
                     meta-proxy ← Seu servidor
```

- **Receber:** quando uma mensagem chega, o Coexy entrega via POST para sua URL de webhook
- **Enviar:** seu servidor chama o meta-proxy com o `channel_token` e o Coexy encaminha para a Meta

<Note>
O Coexy já suporta **envio e recebimento** de mensagens WhatsApp hoje. O envio é feito via **meta-proxy** — não é necessário nenhuma outra plataforma ou integração externa.
</Note>

## Pré-requisitos

- Uma conta no [Coexy](https://coexy.com.br)
- Uma API Key (gerada em **Configurações → API Keys**)
- Um endpoint HTTPS público para receber eventos (ou uma Supabase Edge Function)
